A) ตั้งค่าให้รันได้ด้วยพอร์ตเดียว (80) — ยืนยันด้วยการรันจริงแล้ว
   - Frontend/vite.config.js: เพิ่ม build.outDir ให้ชี้ตรงไปที่ ../Backend/public (พร้อม emptyOutDir)
     ผลคือ `npm run build` ที่ Frontend จะเอาไฟล์ static ไปวางที่ Backend/public ให้อัตโนมัติ ไม่ต้อง copy มือ
   - Backend/src/app.js: เพิ่ม express.static(Backend/public) + SPA fallback route (ส่ง index.html ให้ทุก
     path ที่ไม่ใช่ /api/* หรือ /health) วางไว้หลัง route /api ทั้งหมดแล้ว จึงไม่ชนกับ API
   - Frontend/src/services/api.js: BASE_URL เปลี่ยนจาก hardcode "http://localhost:80/api" เป็น relative
     "/api" (ใช้ได้ไม่ว่าจะเข้าเว็บผ่าน host/IP ไหนก็ตาม เพราะ frontend/backend อยู่ origin เดียวกันแล้ว)
   - Frontend/src/lib/socket.js: แก้ตามให้ Socket.IO ต่อ same-origin เมื่อ BASE_URL เป็น relative (เดิมจะ
     กลายเป็น URL ว่างเปล่าและต่อไม่ติด)
   - Backend/.env: ตั้ง NODE_ENV=production, CORS_ORIGINS=http://10.245.97.200, PORT=80 (มีอยู่แล้ว)
   - Frontend/.env: คอมเมนต์ VITE_API_URL ออก (ให้ fallback ไปใช้ relative "/api" ตอน build จริง)
   - ทดสอบจริงแล้ว: build ผ่าน, รัน `node index.js` แล้วยิง curl เข้า http://localhost:80/ (ได้ index.html),
     เข้า path อื่น เช่น /dashboard/whatever (SPA fallback ได้ index.html เหมือนกัน — ใช้งานได้แม้ยังไม่ได้ใช้
     react-router จริงในโค้ดตอนนี้), /health, /api/machine, /api/product, /api/pd-input/master/... ทั้งหมด
     ตอบ 200 ถูกต้อง

1. ยืนยัน/ตั้งค่า Environment Variables ของ Backend บนเครื่อง production จริง (10.245.97.200)
   - [ทำแล้ว] NODE_ENV=production, CORS_ORIGINS=http://10.245.97.200, PORT=80
   - DB_SERVER ตอนนี้ยังเป็น "Sirawit" (ทดสอบวันนี้ต่อฐานข้อมูลนี้ได้จริงจากเครื่องที่รันงานอยู่ — แต่ไม่
     ทราบว่านี่คือเครื่อง production จริงหรือเป็นเครื่อง dev ที่บังเอิญต่อได้) ต้องยืนยันให้ชัดว่าเครื่อง
     10.245.97.200 ต่อ SQL Server ตัวไหน แล้วแก้ DB_SERVER (และอาจต้อง DB_NAME) ให้ตรงก่อน deploy จริง

4. เตรียม process manager ให้ Backend รันค้างไว้ตลอด (ยังไม่มี)
   - เลือกและตั้งค่า PM2 / NSSM (รันเป็น Windows Service) / Task Scheduler ให้ auto-restart เมื่อ crash หรือ
     เครื่อง reboot — ตอนนี้ถ้ารันด้วย `npm start` เฉยๆ แล้ว process ตาย จะไม่มีอะไร restart ให้อัตโนมัติ

5. เรื่อง HTTPS/TLS (ยังไม่มี — ตอนนี้เป็น HTTP ธรรมดาบนพอร์ต 80)
   - Login/รหัสผ่าน/JWT token จะวิ่งเป็น plain HTTP ถ้าไม่มี TLS — ถ้าเป็น intranet ปิดล้อมอาจยอมรับความ
     เสี่ยงนี้ได้ แต่ถ้าต้องการ HTTPS จริงต้องมี reverse proxy (Nginx/IIS) ทำ TLS termination หน้าพอร์ต 80/443
     แล้ว proxy ต่อเข้า backend อีกที (ถ้าเพิ่ม reverse proxy ภายหลัง ต้องเช็คให้ proxy อนุญาต WebSocket
     upgrade ด้วย เพราะ Socket.IO ใช้ websocket)

6. ทดสอบ flow หลักแบบ manual ผ่านหน้าเว็บจริงกับ SQL Server จริง (วันนี้ทดสอบผ่าน curl/API เท่านั้น)
   - สมัคร/login/approve user, สิทธิ์ตาม role (admin/editor/viewer)
   - หน้า dashboard, dl-eff, pd-input ดึง/กรอง/แก้ไขข้อมูลถูกต้อง (โดยเฉพาะฟอร์ม Add/Edit ที่เพิ่งแก้บัค
     dropdown Product Group ไป — ควรทดสอบทั้งกรณี Add ใหม่ และ Edit record เดิม)
   - หน้า Machine Management และ Product Management (รวม tab Product Group) — เน้นเคส "edit เครื่องจักรที่มี
     product group ผูกอยู่แล้วหลายตัว" และเช็คว่า key bug ที่แก้ไปไม่กระทบการแสดงผล/expand แถว
   - real-time update (Socket.IO) push ข้อมูลอัปเดตขึ้นหน้าจอจริงเมื่อมีการเปลี่ยนแปลงข้อมูล (ต้องทดสอบผ่าน
